# Воспроизводимые RTL-регрессии (M3)

[English](REGRESSION.en.md) · [Симуляция](SIMULATION.md) · [Покрытие](COVERAGE.md)

Инструмент `regression_run(cases, timeout_seconds=30)` последовательно выполняет **1–8** проверенных сборок. Каждый случай содержит только два типизированных поля: `build_id` из успешного `build_run` и целый `seed` от 1 до 2147483647. Тайм-аут **каждого** случая — 1–60 секунд. Клиент не задаёт программу, каталог, команды или свободные аргументы.

Пример аргументов (ID условный, не существует):

```json
{
  "cases": [
    {"build_id": "build-0123456789abcdef0123456789abcdef", "seed": 42},
    {"build_id": "build-0123456789abcdef0123456789abcdef", "seed": 42}
  ],
  "timeout_seconds": 30
}
```

До запуска проверяются **все** сборки. Каждый случай записывает `build_status`, `simulation_status`, `verification_verdict`, `simulation_id`, код завершения и факт исполнения. Успешная сборка не становится успешным тестом. Итоговый `regression_status`:

| Условие | Статус |
| --- | --- |
| Все тестбенчи доказали успешную самопроверку | `PASS` |
| Есть хотя бы один фактический отказ | `FAIL` |
| Есть недоступные или незапущенные случаи, но нет отказов | `INCOMPLETE` |
| Есть неубедительный исход без отказов и пропусков | `INCONCLUSIVE` |
| Нет фактических результатов | `NOT_RUN` |

Если артефакт изменился после предварительной проверки, текущий и оставшиеся тесты получают `NOT_RUN`, а не фиктивный успех. При отмене сохраняется частичный `CANCELLED`.

Сохраняются `reg-<uuid>/request.json` и `result.json`, а также массив `replay` с точными парами `build_id`/`seed`. Повтор пары создаёт новый `sim-ID`. Seed обеспечивает воспроизводимость начальных параметров генератора, но **не доказывает** идентичность результатов на разных версиях инструментов и ОС. Покрытие проверяется отдельно через `coverage_report` для конкретной симуляции, а не по числу PASS.

## Приёмка

```bash
uv run python -m unittest discover -s tests -p 'test_regression_unit.py' -v
VERILATOR_MCP_RUN_INTEGRATION=1 uv run python -m unittest discover -s tests -p 'test_regression_integration.py' -v
```

Linux CI выполняет реальную регрессию Verilator по открытым тестбенчам, включая два одинаковых seed; Windows CI проверяет протокол, типы и негативные сценарии. Windows/MSYS2 Verilator — `NOT_RUN`. Успешный тест не заменяет полноценную четырёхсостояниевую верификацию. Не запускайте недоверенные RTL без ОС-изоляции.
