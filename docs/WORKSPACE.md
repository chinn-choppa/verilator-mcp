# Контракт RTL workspace v1

[English](WORKSPACE.en.md)

## Граница доверия

Администратор локального MCP-процесса задаёт **два существующих абсолютных каталога**:

- `VERILATOR_MCP_WORKSPACE_ROOT` — разрешённый проект с RTL-исходниками;
- `VERILATOR_MCP_ARTIFACT_ROOT` — отдельный каталог для результатов будущих операций.

Каталоги не могут совпадать или включать друг друга. Агенту через MCP **нельзя** выбирать корни, создавать каталоги, передавать флаги Verilator или менять конфигурацию процесса. На этом этапе `project_validate` только читает описание проекта, без записи на диск и запуска процессов.

## Версионированный manifest

Файл JSON размещается внутри workspace. Все пути в JSON — нормализованные **относительные пути с разделителем `/`**, включая Windows. Никаких `../`, `C:/...`, UNC, глобов и подстановки переменных. Корень объекта:

```json
{
  "schema_version": 1,
  "top": "top",
  "sources": ["rtl/top.sv"],
  "filelists": ["lists/common.json"],
  "include_dirs": ["rtl/include"],
  "defines": {"FEATURE": "1"},
  "parameters": {"WIDTH": 8},
  "testbench_top": "tb_top"
}
```

Поля `filelists`, `include_dirs`, `defines`, `parameters`, `testbench_top` необязательны. `sources` может быть пустым в корневом JSON, если исходники добавлены через filelist. После развёртывания должен присутствовать хотя бы один исходник. `top` — имя HDL-модуля, а `testbench_top` резервируется для следующего этапа сборки.

Вложенный filelist — **тоже JSON**, а не нативный файл Verilator `-f`:

```json
{
  "schema_version": 1,
  "sources": ["rtl/common.v"],
  "include_dirs": ["rtl/include"],
  "filelists": []
}
```

Вложенные filelists обрабатываются по порядку **раньше** `sources` текущего файла. Повторное включение filelist, циклы и повторные исходники отвергаются; повторяющиеся include-каталоги объединяются с сохранением первого появления. `defines` и `parameters` допускаются только в корневом manifest, сортируются по имени и не наследуются из вложенных JSON.

Числовые параметры: целые 0..2147483647. Макросы: строковые ASCII-значения из букв, цифр, `_` (пустая строка допустима). Имена top/define/parameter используют ограниченное подмножество идентификаторов SystemVerilog; для нестандартных escaped identifiers поддержка будет отдельным решением.

## Лимиты и гарантии

- JSON-файл не более 64 КиБ; глубина вложения до 8; всего до 64 manifest/filelist, 512 исходников `.v`/`.sv`, 64 include-каталогов и 128 define/parameter каждого вида.
- Чтение источников не происходит: проверяется существование файлов и разрешённое размещение; содержимое RTL будет обрабатываться только следующими операциями.
- Символьные ссылки разрешаются через `Path.resolve(strict=True)` и отклоняются, если цель вне workspace; недоступные файлы и нестандартные расширения отклоняются.
- Неизвестные JSON-поля, повторяющиеся JSON-ключи, опасные имена устройств Windows, скрытые команды и свободные флаги отвергаются.
- `config_sha256` фиксирует **нормализованную конфигурацию**, но не хеш содержимого RTL. До запуска реального lint потребуется отдельно зафиксировать хеши входных файлов.

**Остаточный риск:** проверка путей до исполнения процесса не является атомарной защитой от конкурентного изменения symlink и RTL-файлов (TOCTOU). Перед запуском EDA в следующем этапе необходима отдельная политика проверки/снимка входных файлов. Локальный MCP не является OS sandbox: недоверенный RTL может содержать конструкции, влияющие на Verilator, поэтому для потенциально вредоносных проектов нужна внешняя изоляция ОС.

## Проверка

```bash
uv run python -m unittest discover -s tests -p 'test_workspace.py' -v
```

`project_validate("project.json")` возвращает `state=VALID` и `executed=false` только после полной проверки конфигурации. Это **не** означает успешный lint, build или simulation. Отказ MCP приводит к ошибке инструмента и не считается PASS.
