# Политика безопасности

## Сообщение об уязвимости

Не создавайте публичный issue с работающим эксплойтом, токенами или закрытым RTL. Используйте **Report a vulnerability** на вкладке Security репозитория `verilator-mcp` после включения GitHub Private Vulnerability Reporting. Если функция пока недоступна — свяжитесь с сопровождающим проекта через приватный канал, не размещая технические детали публично.

## Модель угроз

MCP-клиент может передавать недоверенные параметры. В будущем сервер сможет запускать сторонний исполняемый файл с правами пользователя — это чувствительное действие даже для локального stdio.

Текущий прототип:

- не выполняет shell/Tcl/DO и не запускает EDA-продукт;
- не читает проектные исходники;
- принимает ограниченный фрагмент текста для разбора диагностик;
- не открывает сетевых портов и не отправляет телеметрию;
- при поиске бинарника не передаёт абсолютные пути MCP-клиенту.

Перед внедрением запуска процессов обязательны: только доверенные бинарники, отсутствие `shell=True`, строгий root для входных и выходных путей, контроль символьных ссылок, время/память/размер логов, корректное завершение дочерних процессов и явное согласие пользователя на операции с побочными эффектами. MCP-аннотации `readOnlyHint` сами по себе не являются ограничением прав.

## Отдельные среды

Не подключайте внешний MCP к закрытым корпоративным исходникам через неутверждённую облачную модель. Локальный `stdio` не гарантирует, что результаты вызовов не покинут компьютер: это зависит и от самого MCP-клиента, и от модели агента.

## Поддерживаемые версии

До первого стабильного выпуска политика сроков исправления не установлена. Все уязвимости оцениваются индивидуально; список поддерживаемых веток появится вместе с первым релизом.
